# 产品设计说明

> 本文记录做这个工具时的需求分析、功能取舍与关键决策，便于后续迭代时不跑偏。
> 结论先行：**这不是一个"计算器"，而是一个"综测季的个人作战室"。**

---

## 一、先问清楚：用户到底在完成什么任务？

如果把需求听成"做一个把分数加起来的网页"，最后交付的会是一个没人用第二次的表单。
真实的 Jobs-to-be-Done 是这四件，且分布在**一整年**而不是评定那一周：

| # | 用户想完成的事 | 发生时间 | 现在他怎么做 | 痛在哪 |
|---|---|---|---|---|
| J1 | **知道我现在大概多少分、离目标差多少** | 全年，随时 | 心算 / 问学长 / 翻 Excel | 规则记不全，封顶规则总忘，算完不敢信 |
| J2 | **决定这学期把时间投在哪** | 学期初、评奖前 | 凭感觉、跟风 | 不知道哪项已封顶、哪项性价比最高 |
| J3 | **评定季把材料一次交齐、别被砍分** | 每学年第一学期 | 临时翻相册/网盘/邮箱 | 材料散落；不知道哪条缺证明；被驳回才发现 |
| J4 | **算清综测之后我到底能不能拿奖 / 能不能保研** | 评定后、公示期 | 只看综测分，忽略加权口径与资格红线 | 综测只是中间量；口径因用途而异；红线一票否决；异议只有 3 个工作日 |

**J2 和 J4 是现有工具（包括各书院的 Excel 表）完全没覆盖的**，也是本工具的主要差异化价值所在。

## 二、目标用户与场景细分

**主力用户：大一到大三本科生**（大四基本没有综测压力，但要用于推免复核）。

三类典型人格，功能优先级完全不同：

- **「精算型」**（约占 15%）：开学就在算，目标明确（保研/国奖）。
  → 需要：多口径综合成绩、目标反推、班级对比排名、情景模拟。
- **「被动型」**（约占 70%）：评定通知下来才开始翻材料。
  → 需要：材料清单、缺什么一眼看到、导出自评表直接交、申诉时效别错过。
- **「踩坑型」**（约占 15%）：有旷课/卫生/处分记录，或论文署名写错单位。
  → 需要：红线预警、扣分不设上限的直观冲击、资格自检。

设计结论：**仪表盘必须同时服务三类人**——顶部给精算型看数字与目标，中部给被动型看待办与风险，底部给所有人看规则边界。因此仪表盘的信息架构是"总分 → 提示 → 计算过程 → 剩余空间"，而不是一个大数字加一堆图表。

## 三、关键设计决策（含被否决的方案）

### D1. 规则做成"数据 + 可配置"，而不是写死在代码里
**问题**：集体活动 0.6 分/次是彭康口径；任职不满一年的折减幅度各书院不同；综合成绩权重按用途分好几种。写死 = 工具只对一部分人正确，而且错得很隐蔽。

**决策**：
- `rules.js` 是唯一的规则数据源，引擎不认识任何具体数字；
- 三级覆盖：`校级默认值 → 全局自定义 → 当前档案 ruleOverride`；
- 凡是校级办法说"由书院认定"的地方，UI 上就地标注 ⚑ 与原文，并提供修改入口。

**否决方案**：为每个书院做一个预设包。原因：无法穷尽核验、且书院细则每年会改，硬编码只会制造"看起来很确定其实不确定"的假象——这比不给答案更糟。

### D2. 计算过程必须可审计
**问题**：这类工具最大的信任障碍是"它算的和我想的不一样，我不知道谁错了"。

**决策**：
- 引擎输出的每一项都带 `points / reason / counted / blocked`；
- 「计算过程」面板逐行展示 `原始合计 → 封顶 → 最终`；
- 溢出明确写出"原始 21 → 封顶 10，溢出 11 分不计"；
- 被合并的条目在列表里标"同一项目取最高·未计入"并划掉分值；
- 导出的自评表带完整计算轨迹，可以直接拿给辅导员核对。

### D3. 情景模拟用"草稿沙盒"而不是独立表单
**问题**：学生最想知道的是"如果我再做一件事会怎样"。做一套独立的假设输入表单，等于把录入界面重做一遍，还要维护两套逻辑。

**决策**：进入模拟模式后，`ZC.getProfile()` 返回草稿副本，**全站所有页面照常可用**，改的都是草稿；对比页实时显示差值；可一键应用或丢弃。
额外收益：可以用真实界面模拟"旷课 3 次 + 处分"这类复杂组合，而不只是加加分项。

**否决方案**：只保留 26 个一键假设按钮。保留了它们作为低门槛入口，但完整模式才是主力。

### D4. 材料状态是一等公民，不是备注
**问题**：综测评定的实质是材料评定。一个只有分值的工具，会在最需要它的评定季失效。

**决策**：每条加分项自带 `佐证材料` + `材料状态`（未准备/待提交/已提交/已认定/被驳回），跨板块自动汇总成材料清单，并统计"有多少分悬在材料没备好的状态"。仪表盘会主动提醒"2 条加分项尚未备好证明材料，涉及约 1.86 分"。

### D5. 提示引擎要"可执行"，不要"正确的废话"
**问题**：温馨提示很容易做成一堆"请注意规则"的空话。

**决策**：每条提示必须满足三条之一——指出具体风险后果、给出具体下一步动作、给出具体数值差。例如：
- ❌"请注意志愿服务时长要求"
- ✅"志愿服务还差 11 小时。补齐可再得约 0.34 分。按学年累计，别拖到学年末。"
- ✅"学术科研已封顶 10 分（原始 21）。继续堆同类成果不涨分，建议转向文体竞赛（还可 +4.5）或任职（还可 +2.5）。"
- ✅"旷课已累计 4 次。累计到一定程度可能构成纪律处分（警告 −4 起），并直接触发奖学金参评资格红线。"

提示按 `风险 → 待办 → 机会 → 规则` 四级排序，可筛选。

### D6. ROI 推荐引擎
**问题**：告诉学生"还能拿 X 分"不够，得告诉他"先做哪件"。

**决策**：维护一份机会目录（28 项），每项标注归属分项、分值、投入等级；
`实际收益 = min(该项分值, 该分项剩余空间, 能力拓展总剩余空间)`，
`ROI = 收益 / 预估投入小时`，按 ROI 降序输出；
支持"目标反推"：给定目标分，贪心选出最小组合并显示累计进度。
同时**明确标注**投入小时数是经验估计、仅用于排序——避免制造虚假精确感。

### D7. 综合成绩必须多口径，且标注来源
**决策**：内置 5 套预设（奖学金 80/20、转专业分流 90/10、推免示例 90/10、崇实书院 20/70/10、自定义），每套都写明出处，并显示"综测每 +1 分 → 综合成绩 +X 分"的敏感度。
额外提供"综测是否折算为百分制"开关——因为综测满分 105 与百分制课程成绩直接加权在量纲上是有争议的，不同学院处理方式可能不同，工具不替用户做假设。

### D8. 纯静态、单文件、无框架
**问题**：目标用户是学生，分发渠道是微信/QQ/网盘/U 盘，使用环境是宿舍笔记本和手机。

**决策**：
- 无后端、无账号、无埋点、无 CDN 依赖 → 可完全离线；
- 构建产物是**单个 `index.html`**（264 KB）→ 双击即用，也能在受限的网页预览窗口里完整渲染；
- 不用 React/Vue：避免构建链与 CDN 依赖，同时保留源码可改性（`src/` 是分文件的，改样式只动一个 CSS）；
- 不用 ES Module：`file://` 协议下模块会被 CORS 拦截，必须用传统 script + 命名空间。

**代价**：自己实现状态管理与重渲染。用"`data-k` 路径双向绑定 + 焦点/滚动还原"解决了输入体验，代码量可控。

### D9. 明确不做的事

| 不做的功能 | 原因 |
|---|---|
| 账号系统 / 云同步 | 引入后端与隐私合规成本，与"纯静态"定位冲突；用 JSON 导入导出替代 |
| 自动抓取教务/志愿系统数据 | 无官方开放接口，爬虫方案不稳定且有合规风险 |
| 全班协同填报 / 排行榜社交化 | 隐私敏感，且真实排名由书院公示，工具不应制造"民间榜单" |
| 移动端独立 App / 小程序 | 超出交付范围；响应式 Web 已覆盖手机场景 |
| 官方规则库自动更新 | 无法保证准确性；改为在 UI 与文档中持续标注"以书院当年公示为准" |
| AI 问答式规则咨询 | 规则手册 + 搜索高亮已能满足查询，且答案可控、可溯源 |

## 四、信息架构与交互取舍

### 导航分三组：计分 / 工具 / 参考
对应三种使用频率：评定季高频（计分）、决策期高频（工具）、低频但关键（参考）。

### 常驻计分条（顶栏）
在任何页面都能看到 `品行 X/80 · 能力 Y/20 · 奖励 Z/5 · 总分 T/105 · 距目标 ±N`。
理由：录入是分页的，但用户的心理账户是总分。没有常驻反馈，录入过程会变成"盲填"。

### 每个板块页头显示本页得分与构成公式
例如品行页头：`满分 80 分 = 基准分 70 + 集体活动 ≤3 + 思政学习 ≤3 + 社会服务 ≤4 − 扣分（不设上限）`。
把规则写在使用现场，比让用户去翻手册有效得多。

### 分值表就地展示
学术/文体/任职板块都把官方分值表渲染在录入区上方。录入时能直接对照，减少"我这算几等奖"的犹豫。

### 步进器而非纯输入框
思政学习、社会服务这类"次数"字段用 `− 数字 +` 步进器：手机上好点，且天然防止负数。

### 输入即重算，但不失焦
每次输入触发全视图重渲染（保证任何联动都正确），通过记录 `data-k` 与光标位置在重渲染后精确还原焦点。用户感知是"实时计算"，而不是"填完再点计算"。

## 五、质量保障

- **138 项计分单元测试**：覆盖每一个分值表的每一个格子、每一处封顶、同一项目取最高、兼任取最高、任期 4 种口径、署名单位正反例、扣分下限、4 套综合成绩口径、工作日推算、报表生成。
- **50 项渲染测试**：11 个视图 × 多种极端数据（空白档案 / 评议未通过 / 50 条扣分 / 全部封顶 / 12 条同名项目 / 脏数据与非法枚举 / 公示日已过），并自动扫描模板里出现的 `data-act`、`data-nav`、`data-k`、规则原文键，确保**没有死链接、没有未注册动作、没有非法绑定路径**。
- **7 项降级测试**：localStorage 完全不可用（沙箱预览、无痕模式、配额超限）时仍能启动、录入、渲染、模拟。
- **XSS 测试**：用户输入的 `<script>`、`<img onerror>` 在列表、材料清单、仪表盘均被转义。

跑测试：
```bash
node tests/engine.test.js     # 计分规则
node tests/render.test.js     # 渲染与交互
node tests/degraded.test.js   # 存储降级
```

## 六、后续可迭代方向（按价值/成本排序）

1. **书院口径预设包**（高价值/中成本）：在拿到各书院当年公示细则后，做成一键切换的预设，并在 UI 上标注来源与年份。
2. **学年趋势对比**（高价值/低成本）：已有 `classmates` 与多档案结构，加一个大一→大四的分数折线即可。
3. **材料清单的截止日提醒**（中价值/低成本）：给每条材料加 `dueDate`，仪表盘按紧急度排序。
4. **PWA 离线安装**（中价值/中成本）：加 manifest + service worker，可"安装到桌面"。注意 `file://` 下 SW 不可用，需通过 http 访问才生效。
5. **导出 Word 版自评表**（中价值/中成本）：目前导出 Markdown/CSV/PDF（打印），部分书院要求固定格式的 Word 表格。
6. **班级批量导入模板**（低成本）：`classmates` 已支持粘贴导入，可再加 CSV 模板下载。

## 七、一句话总结

> 把一份"没人愿意读完的细则"，变成一个**随时能问、算得可信、还会主动提醒你别踩坑**的工具；
> 并且诚实地标注出哪些是校级统一规定、哪些是书院自己定的——因为在这件事上，**虚假的确定性比不确定更有害**。

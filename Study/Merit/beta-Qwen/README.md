# 综测算分器 · 西安交通大学本科生综合素质测评

> 纯静态单页应用 · 无后端 · 无依赖 · 可离线 · 数据只存在你自己的浏览器里

一个帮交大小朋友把「综合素质测评」这件事**算清楚、备齐材料、想明白下一步该干什么**的工具。

---

## 一、30 秒上手

| 场景 | 怎么做 |
|---|---|
| **直接用** | 双击 `index.html`（Chrome / Edge / Safari 均可），无需安装、无需联网 |
| **改样式/逻辑** | 编辑 `src/css/app.css`、`src/js/*.js`，改完直接刷新 `src/index.html` 看效果 |

`设置 → 数据管理 → 清空当前档案`。

## 二、为什么做成这样：需求分析

综测的真实痛点不是"不会算加法"，而是这四件事：

### 1. 规则复杂 + 各书院口径不一 → **算不准**
- 7 个分项各有封顶（3 / 3 / 4 / 10 / 6 / 4 / 5），超出的部分**白干**；
- "同一项目取最高"、"兼任取最高"、"志愿服务按比例"、"专著第 4 位起依次递减"这类规则，手算极易出错；
- 集体活动单次分值、任职不满一年怎么折减，**校级办法没写死，由书院认定**。

> 对策：规则全部做成**数据驱动的可配置项**，校级办法作为默认值，书院口径一键覆盖；每一分都给出计算依据，并提供可逐行核对的「计算过程」面板。

### 2. 综测是"材料评定" → **加分被砍**
没有佐证材料的加分，在班级评议阶段极易被剔除。竞赛证书、录用通知、专利证书、志愿时长截图、任职文件、主办单位名单……散落在四处，等到集中评定那几天根本找不齐。

> 对策：录入时就带**佐证材料 + 材料状态**（未准备/待提交/已提交/已认定/被驳回）字段，自动汇总成「材料清单」，并统计有多少分悬在"材料没备好"的状态上。

### 3. 不知道下一步该干什么 → **性价比错配**
学术科研封顶 10 分，已经满了还在肝竞赛；文体还剩 4.5 分空间却没人动；一次旷课 −1 分，等于白拿一个校级优秀奖。

> 对策：**投入产出比引擎**。按"剩余空间 × 单位时间收益"排序，直接告诉你最划算的 6 件事；支持"目标反推"（我想考到 92 分，最少要做哪几件事）。

### 4. 规则陷阱与时效 → **一票否决 / 丧失程序权利**
- 必修课不及格（**补考、重修视同不及格**）或受纪律处分 → 直接取消当年奖学金参评资格；
- 论文第一署名单位不是西安交大 → 不予认定；
- 公示起 **3 个工作日**内不提异议，之后就没有程序救济了；
- 推免/复试的"综合素质测试"是**心理测评**，跟综测加分完全无关（很多人白紧张一场）。

> 对策：参评资格自检（红线勾选）、署名单位自动校验、工作日时效计算器 + 申诉文书模板、规则手册内置全部易混淆点。

### 5. 综测只是中间量 → 学生真正关心的是**综合成绩和排名**
评奖学金 = 课程成绩 × 80% + 综测 × 20%；转专业/分流公开口径是智育 90% + 综测 10%；推免占比因学院而异；崇实书院 2015 细则甚至是德育 20% + 课程 70% + 体育 10%。

> 对策：内置 **5 套综合成绩口径**可切换（含来源出处），联动显示"综测每 +1 分 → 综合成绩 +X 分"的敏感度；「班级对比」页可录入同学成绩估算排名与奖学金档位。

### 几个值得一提的实现细节

- **情景模拟的"草稿模式"**：进入后全站所有页面都在编辑一份草稿副本，正式档案不受影响，对比页实时显示差值；满意就一键应用，不满意直接丢弃。这比做一套独立的"假设表单"强大得多，且零学习成本。
- **封顶透明化**：每个分项都显示"原始合计 → 封顶后"，溢出多少分不计一目了然，避免"我明明拿了 21 分学术成果为什么只有 10 分"的困惑。
- **在职任职的语义**：任期结束日留空 = 在职中，按"预计做满一年"计分，同时提示"若现在退任只能拿 X 分，差价 Y 分"——既不吓唬人，又给出决策信息。
- **署名单位智能校验**：归一化后匹配，能识别 `西安交通大学` / `Xi'an Jiaotong University` / `Xian Jiaotong Univ.` / `XJTU` / `西安交通大学第一附属医院`，同时**不会**把"北京交通大学"误判为西交大。
- **焦点保持的重渲染**：无框架实现 React 式的"输入即重算"，通过记录 `data-k` 与光标位置，在重渲染后精确还原焦点，输入体验不卡顿、不跳位。
- **存储降级**：检测到 localStorage 不可用（受限预览窗口/无痕模式）时自动降级为内存存储并明确告知，不会静默丢数据、也不会满屏报错。

## 四、计分规则实现对照

**总公式**：`综合素质测评成绩 = 品行素质分(80) + 能力拓展分(20) + 奖励分(5)`，满分 **105**。

| 板块 | 分项 | 上限 | 实现要点 |
|---|---|---|---|
| 品行素质分 | 基准分 | 70 | 评议合格开关控制 |
| | 集体活动 | 3 | 单次分值可配（默认 0.6，彭康口径）；突出贡献一次性满分 |
| | 思政学习 | 3 | 党团培训 +1 / 省部级 +2 / 优秀学员额外 +1，可叠加后封顶 |
| | 社会服务 | 4 | 志愿 ≥32h 得 1 分，**不足按比例**；实践/挂职/见习/表彰各项累计后封顶 |
| | 扣分 | **不设上限** | 通报 −2、警告 −4、严重警告 −6、记过 −8、留校察看 −10、旷课 −1/次、宿舍卫生 −1/人·次；默认扣到 0 为止（可关） |
| 能力拓展分 | 学术科研 | 10 | 竞赛三级四档；论文/专利/专著按类别 × 署名位次；**同一项目取最高**；署名单位校验 |
| | 文体竞赛 | 6 | 文艺/体育分表；破省级及以上纪录 +5、破校级 +3；同一项目取最高 |
| | 组织任职 | 4 | 四档 × 优良合格；**兼任取最高不累加**；不满一年按可配口径折减；不合格不加分 |
| 奖励分 | 荣誉/见义勇为/做好事 | 5 | 全国 5·省 4·市 3·校 2·院 1；做好事每项 +1；累计超 5 按 5 |

完整规则原文与来源核验见 [`docs/规则依据.md`](docs/规则依据.md)。

### 架构约定

- **无框架、无构建依赖**：原生 JS + IIFE 模块，通过 `window.ZC` 命名空间通信。不用 ES Module 是为了能直接 `file://` 双击打开。
- **规则与代码分离**：所有分值、上限、口径都在 `rules.js` 里，改规则不用碰引擎。
- **引擎是纯函数**：`ZC.compute(profile, rules) → result`，不改入参，输出含每一项的 `points / reason / counted / blocked`，因此「计算过程」「材料清单」「导出报表」「提示引擎」全部复用同一次计算结果，绝不会出现"页面显示的分和导出的分不一致"。
- **单一渲染入口**：任何状态变更 → `ZC.rerender()` → 重算 + 重绘当前视图 + 还原焦点/滚动位置。
- **事件全委托**：`data-k="路径"` 自动双向绑定到档案对象（支持 `a.b[0].c`），`data-act="动作"` 自动派发到 `ZC.actions`。加一个字段只需写一行模板。

## 六、二次开发速查

**改配色**：只动 `src/css/app.css` 第 0 节 `:root` 里的变量（深色模式在 `[data-theme=dark]`）。

**改某个分值**：动 `src/js/rules.js` 的 `ZC.DEFAULT_RULES`。例如把集体活动默认单次分值从 0.6 改成 1.0：
```js
collective: { perTime: 1.0, ... }
```

**加一种新的扣分类型**：在 `rules.js` 的 `pinxing.deduction.types` 里加一项即可，UI、计分、报表会自动跟着变。

**加一个新的"机会"到 ROI 推荐**：在 `rules.js` 的 `ZC.OPPORTUNITIES` 里加一条（指定 `cap` 归属分项，引擎会自动用该项剩余空间裁剪收益）。

**加一个新页面**：在 `views-*.js` 里写 `ZC.views.xxx = { render(ctx){ return html }, after(ctx){} }`，再到 `app.js` 的 `ZC.NAV` 里加一项。

**改完记得**：`python3 build.py` 重新生成单文件版，并跑一遍 `node tests/*.test.js`。

## 七、数据与隐私

- 所有数据保存在**本机浏览器的 localStorage**（键名 `xjtu_zongce_v3`），不联网、不上传、无账号、无统计埋点。
- 清除浏览器数据 / 换设备 / 换浏览器都会丢失 → 请定期 `导出备份 (JSON)`。
- 「班级对比」需要录入同学成绩，**请自行获得同意并尊重他人隐私**，不要录入学号等敏感信息；该功能仅用于自我定位估算。

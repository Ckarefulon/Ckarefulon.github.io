# 综测算分器 · 西安交通大学本科生综合素质测评

> 把「综合素质测评」这件事算清楚、备齐材料、想明白下一步该干什么。
> 纯静态页面 · 数据本机保存 · 登录后可与云端同步（Supabase，账号与本站其它工具共用）。

页面地址：`/Study/Merit/`

---

## 一、这是什么

`Study/Merit/` 下原来有两个 beta（`beta-Qwen`、`beta-step`），功能互补但各缺一半：
一个功能全、视觉糙；一个交互顺手、功能薄。本目录的成品是两者的融合版，
再加上站点统一的 Supabase 云同步，成为这个目录唯一的入口页。

**一句话取舍：**

| 来源 | 取它的 | 弃它的 |
|---|---|---|
| `beta-Qwen` | 计分引擎与可审计轨迹、投入产出比推荐、材料清单、情景模拟、班级对比、程序时效、规则手册、综合成绩多口径、多档案、撤销、导入导出报表 | 桌面优先的版式、过重的组件与样式体系 |
| `beta-step` | 移动优先的观感：总分环形进度 + 分区进度条、开关/步进器/分段器、选项上直接标分值、扣分不设上限的强提示、按次数与按突出贡献两种集体活动口径 | 简化的数据模型（没有材料状态、任期起止、署名单位等） |
| 站点既有约定 | 设计令牌 `dsk-*`、`nav.js` 顶栏、`site-scope.js` 作用域、Supabase 登录态与 `user_data` 表 | — |

## 二、能做什么

### 计分（四页）

- **概览**：总分环形进度、三区分解、目标分与差距、综合成绩、提示与风险、投入产出比最高的 6 件事、可逐行核对的「计算过程」、各分项封顶与溢出。
- **品行素质分**（80）：基准分开关、集体活动（按次数 / 突出贡献一次性满分，单次分值随书院口径）、思想政治理论学习、社会服务（志愿时长按 32 小时比例折算）、扣分（不设上限的 8 类）。
- **能力拓展分**（20）：学术科研（竞赛 / 论文 / 专利 / 专著，含「同一项目取最高」与第一署名单位校验）、文体竞赛（文艺 / 体育，含破纪录加分）、学生组织任职（四档 × 考核等级，兼任取最高，任期不满一年按实际月数折减）。
- **奖励分**（5）：按级别计分的荣誉表彰、见义勇为，以及每项 +1 的「做好事」类。

### 工具（五页）

- **综合成绩 · 资格**：5 套加权口径（奖学金 / 转专业分流 / 推免示例 / 崇实书院细则 / 自定义）、综测敏感度、奖学金参评资格红线自检、奖学金档位与体测门槛。
- **材料清单**：跨全部条目汇总，状态（未准备→待提交→已提交→已认定→被驳回）与佐证材料可直接改，附各类材料准备要点。
- **情景模拟**：26 个一键假设（含「如果出事了」的反向模拟），草稿模式可把全站当沙盘玩，实时对比综合成绩，可应用 / 重置 / 丢弃；目标分反推要做哪几件事。
- **班级对比**：录入同学成绩估算排名、百分位与奖学金档位，支持批量粘贴，名额比例可改。
- **程序与时效**：公示日起 4 个关键截止日（按工作日推算，跳过周末）、8 步评定流程、可复制的申诉文书模板。

### 参考（两页）

- **规则手册**：校级办法速查 + 关键词搜索高亮，⚑ 标出常见误解（0.6 分/次的书院属性、不满一年的酌情空间、推免「综合素质测试」其实是心理测评等）。
- **设置**：档案信息、书院口径与规则参数、云同步、数据管理（JSON / Markdown / CSV / 打印）、多档案管理。

## 三、文件

```
Study/Merit/
├─ index.html          ← 页面入口（站点 head、nav、Supabase 脚本顺序）
├─ merit.css           ← 全部样式：桌面左侧栏 + 移动端顶部分栏两套布局
├─ merit-rules.js      ← 规则单一数据源（分值表、上限、口径、机会目录、规则手册正文）
├─ merit-engine.js     ← 计分引擎（纯函数，输出可审计轨迹与综合成绩）
├─ merit-insights.js   ← 提示引擎 / 投入产出比推荐 / 材料汇总
├─ merit-ui.js         ← 图标、环形进度、进度条、开关、步进器、分段器等渲染片段
├─ merit-store.js      ← 状态、本机持久化、档案、撤销、导入导出、Supabase 云同步
├─ merit-views.js      ← 11 个页面视图
├─ merit-app.js        ← 外壳、路由、事件委托、渲染调度、动作表
├─ beta-Qwen/          ← 融合前的一版（保留作对照）
└─ beta-step/          ← 融合前的另一版（保留作对照）
```

### 架构约定

1. **规则与代码分离**：所有分值、上限、口径、机会目录都在 `merit-rules.js`；改分不用碰引擎。
2. **引擎是纯函数**：`ZC.compute(profile, rules) → result`，不改入参；每一项都带 `points / reason / counted / blocked`，因此「计算过程」「材料清单」「导出报表」「提示引擎」共用同一次计算，不会出现页面与导出的分不一致。
3. **字段与动作两条委托线**：`data-k="路径"` 自动双向绑定到当前档案（支持 `a.b[0].c`），`data-act="动作"` 派发到 `ZC.actions`。加一个字段通常只需写一行模板。
4. **单一渲染入口**：任何状态变更 → `ZC.rerender()` → 重算 + 重绘当前视图 + 还原焦点/滚动。视图只负责把 `ctx` 渲染成 HTML。
5. **口径可覆盖**：校级默认值在 `DEFAULT_RULES`；`globalRules`（全局）与 `profile.ruleOverride`（单档案）逐层深合并，设置页改的就是这两个对象。

## 四、计分规则只有一份（与两个 beta 的核对）

融合后不存在「两套分」：`merit-rules.js` 是唯一数据源，引擎、界面上的选项分值、规则手册、导出报表全部读它，
改一个数字全站一起变。

核对脚本 `.tests/merit-rules-diff.js` 把三份实现各自跑在独立的 vm 上下文里，比四层：
**枚举项集合 → 逐格数值 → 缺省回退行为 → 合并规则（取最高 / 封顶 / 兼任 / 触底）**。
最近一次结果：111 个数值格（三方一致 107、表示方式不同 3、数值分歧 1）+ 15 个行为探针（不一致 5）。

已统一的部分（三份实现完全一致）：竞赛三级四档（含**特等奖**）、论文 i/ii 类与一般期刊、
文艺/体育各级、任职四档 × 优/良/合格、奖励五级、基准分 70、三项上限 3/3/4、
志愿 32 小时按比例、七类固定扣分。

**专著署名**按原文「第四位起依次递减 1」展开成完整表：

| 位次 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 及以后 |
|---|---|---|---|---|---|---|---|---|---|
| 分值 | 10 | 8 | 6 | 5 | 4 | 3 | 2 | 1 | 1（下限） |

表内没有的位次统一走 `rest` 回退：专著 `rest = 1`，一般期刊 `rest = 0`（不计分）；参编 +1 不变。
（beta-step 原先把第 4 位写死成 1 分，与它自己的说明矛盾，已按原文改为 5 并补到第 8 位。）

**仍存在的差异（都在 beta 参照页，不影响成品）：**

| 差异 | beta-step | Qwen 系 / 融合版 |
|---|---|---|
| 同一项目获多个奖 | 只做分组求和（未实现「取最高」） | 取最高、不累加 |
| 兼任多项职务 | 求和后截断（4 + 0.5 恰好同值，2 + 2 会翻倍） | 取最高 |
| 扣分扣到负 | 允许出现负分 | 扣到 0 为止 |
| 任职「不合格」、专著第 9 位以后 | 无该枚举（只能靠文字说明） | 显式枚举 + 表外回退 |

若你所在书院对某格另有细则（专著递减幅度、集体活动单次分值、任职不满一年的折减系数），
前两项能在「设置 → 书院口径」里改；专著递减表本身在 `merit-rules.js` 的 `publication.classes`。

### 「同一项目取最高」按什么归组

归组键只有一处实现（`merit-engine.js` 的 `groupKey()`）：

| 条目类型 | 归组字段 | 界面上的位置 | 缺省行为 |
|---|---|---|---|
| 竞赛 / 论文 / 专利 / 专著 | `ability.academic[i].project` | 条目编辑器的「项目 / 成果名称」 | 论文/专利/专著带 `noMerge=true`，**不参与归组**，每项独立计分 |
| 文艺 / 体育 | `ability.culture[i].name` | 「赛事名称」 | 空名时各自成组 |
| 学生组织任职 | —（按规则「兼任取最高」） | — | **全类取最高**，这是规则要求的，不是按项目分组 |

规则细节：

- 键 = `trim()` + 转小写后的项目名；前后空格、大小写差异视为同一项目。
- 项目名为空 ⇒ 退回按条目 `id` 分组，**两条没填名字的记录不会互相吞掉**（各自计入）。
- 学生组织任职是「兼任多项职务按最高分计」，本来就跨全部任职取最高；其余分项都是先按项目归组、组内取最高，再对分项封顶。
- 想验证：`node .tests/merit-project-group.test.js`（把归组键、每条是否计入、被舍弃的分值都打出来）。

## 五、数据与云同步

- **本机**：`localStorage`，键名 `merit.zongce.v1`。检测到不可用（无痕 / 受限预览）时降级为内存存储并明确提示，不会静默丢数据。
- **云端**：Supabase `public.user_data`，`site_scope = Study-Merit`（由 `/assets/services/core/site-scope.js` 按路径计算，未登记路径一律不同步，绝不兜底到别的作用域）。
- **登录**：用站点顶栏右上角的账号入口，与 Formula、Question 等页面共用同一个账号。
- **合并策略**：按档案 `id` + `updatedAt` 取新；删除写墓碑（`deleted[id]`），别处的旧副本会跟着消失；`app = study-merit` 作为归属标记，作用域里发现其它站点的数据就停止上传并提示冲突。
- **压缩**：上传前走 `payload-codec.js`（gzip），缺这个脚本时自动退回明文上传，功能不降级。
- **自动同步**：改动后 1.4 秒防抖上传；设置页可关自动同步、手动上传 / 恢复、退出登录。
